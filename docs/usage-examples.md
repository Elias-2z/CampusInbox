# CampusInbox 使用示例

以下均为合成通知。先启动仓库根目录主应用，打开 `http://127.0.0.1:5173`。导入时核对原消息发送时间和时区，相对日期据此计算。

## 创建第一条任务

进入「我的任务 → 新建任务」，粘贴下面的通知，也可使用表单中的示例：

```text
软件工程：明天18:00前提交需求分析报告，上传至学习通，文件命名为学号+姓名。
```

整理后，在收件箱核对课程、任务名称、截止时间与要求，再确认创建。点击识别标签查看字段依据。没有安装模型也可以使用规则和人工审核。

## 延期更新

1. 先手动创建“数据库原理”的“实验四报告”，设置未来的截止时间。
2. 导入“数据库原理：实验四报告延期到下周一晚上八点，其他要求不变。”。
3. 在收件箱选择原任务，点击“预览这次变更”，核对新旧截止时间后确认。
4. 到任务详情查看关联原文与历史；在没有后续修改冲突时，可撤销本次更新。

原任务仍只有一条。候选不唯一时需要选择；无法确定的时间需手动核对。

## 取消通知

先创建“数据库原理”的“实验四报告”，再导入：

```text
数据库原理：实验四报告取消，不用再提交。
```

选择目标任务、预览后确认取消。任务内容和来源仍保留，可以到详情查看记录及撤销操作。问句、否定和复杂歧义不应直接按取消处理；后续编辑可能阻止旧撤销覆盖。

## 多任务通知

```text
软件工程：
1. 下周一晚上八点前提交需求分析报告。
2. 下周三下午六点前提交原型设计，上传至学习通。
```

在收件箱生成拆分草稿，逐项核对、保存、创建或跳过。支持从 1 开始、连续编号且每项另起一行的 2–20 项；未确认条目不会直接成为任务。不同任务的日期与要求需分别核对，公共说明请对照原文。

## 重复通知关联

先手动创建“软件工程”的“需求分析报告”，设置未来截止时间，不填写提交平台。再导入：

```text
软件工程：明天18:00前提交需求分析报告，上传至学习通，文件命名为学号+姓名。
```

选择“关联已有任务”，只勾选提交平台和文件要求，预览后确认。原任务仍只有一条，未勾选的截止字段保留原值。也可以不选字段，只关联来源。课程、任务类型或序号冲突时不能关联。

## 重新识别已有任务

在“我的任务”点击“重新识别”，必要时选择一条原始通知。查看新旧字段差异，勾选需要采用的建议后确认；仅查看预览不会修改任务，保存前仍会检查任务版本。

## 截止提醒与日历

新建一个截止时间为未来一小时的待办，进入“提醒”查看卡片，尝试已读或稍后提醒。完成任务或到期后，当前提醒列表会移除对应记录。站内检查依赖页面打开，Windows 托盘需要后端持续运行；设置与限制见[提醒说明](reminders.md)。

在“日历”切换周 / 月和课程筛选，点击任务进入详情。“导出当前视图 .ics”可下载对应日期范围及筛选的任务，再手动导入日历客户端；它不会自动同步更新，也不额外设置闹钟。已过截止的任务不出现在当前日历结果中，原任务仍可在“我的任务”的“全部”筛选查阅。详见[日历说明](calendar.md)。

## 图片与文件导入

新建任务时选择图片或文件上传，先核对提取文字再整理任务。TXT / Markdown / DOCX 支持本机正文提取；图片和 PDF 取决于本机 OCR 或已配置的解析服务。原件、部分解析及失败状态都需要核对，不能把文字提取成功视为任务字段完全正确。支持范围、大小限制与 MinerU 配置见[附件说明](task-import.md)。
