# 主项目融合进度

此分支仍在开发，不代表 `local-assistant/` 已完整迁入主项目。原扩展和主项目目前仍使用各自数据库；不要删除原扩展或其数据目录。

## 已接入主项目，仍需实机验收

- 学习通连接入口、消息持久化和收件箱审核；设置页可查看各来源本次运行的检查状态、未处理数量与心跳。已下载附件可查看或下载。TXT / Markdown 在本机读取。学习通已下载的 DOCX 在同步开启期间排队本机提取，支持中断后续处理。支持本机 OCR 的 Windows 环境也会排队处理已下载的图片和 PDF，并支持手动重试。重新识别时，最多检查 5 份已完整提取文字的附件，只有一份给出明确任务时才采用并标明文件依据。附件缺失、部分 OCR、任务或日期线索冲突时须人工核对；缺失附件补齐及平台状态同步仍不完整。
- 学习通任务有明确已过截止日期且未匹配已有任务时，可进入收件箱“历史归档”，原文保留且可恢复；其他历史归档规则尚未完整迁移。
- 学习通任务状态可按账号、课程、班级和平台任务编号核对，用户确认后采用；不凭任务名称匹配，超过 24 小时的记录不能直接采用。此操作只更新本地任务，不代替在学习通提交作业；真实账号仍待验收。
- 已关联的同一作业仅发生平台状态变化时，更新核对依据并复用原通知，避免退回重做时产生第二份任务草稿。确认恢复待办后，历史记录保留平台状态和核对时间。正文或原件确有变化仍作为新内容处理。
- 任务详情可请求当前账号的采集器重查已发现的关联作业。采集返回新状态后可刷新本地记录，更新任务仍须确认。补充了“提交成功”“待重新提交”等明确状态别名。
- 同一通知的附件原件延迟到达时，按文件名称和来源地址补入现有记录。相同地址的文件字节发生变化时保存为新版本。课程通知中有规则依据、明确年份且已过截止的任务可进入历史归档，已有任务匹配与变更通知仍待审核。
- 可识别明确的日期或具体时刻，并保留学习通任务的结构化截止依据；正文与平台冲突时留待人工核对。支持已做完与已提交状态、任务列表和日历显示；已有的“已完成”状态保留其原含义。
- 学习通正文和附件中的日期需要在同一语句内有截止或提交依据。发布时间和实验安排保留在原文，不能作为任务截止时间或历史归档依据；本地模型仍可辅助其他字段。
- 学习通课程通知和聊天原文中的明确实验安排，在收件箱单独展示原句。相对日期保留原写法，活动安排独立于提交截止。
- 任务详情中可手动维护材料清单，也可从原文及已解析附件提取建议、逐项核对后加入；拆分任务仅使用对应正文，避免混入其他任务要求。清单随任务版本记录变更。当前只覆盖明确的提交、上传和上交表述，不保证识别全部要求。
- 手机提醒配对控制入口；需要 Android 设备验证配对、网络通信、通知及断开流程。
- 浏览器通知可在设置中主动授权。Windows 可另外启动托盘，网页关闭后仍从主项目读取截止提醒，启动时跳过首次已有提醒，后续按提醒编号和版本去重。
- 主项目 QQ 桥接在 Windows 使用系统凭据管理器，模拟测试已覆盖；仍需真实 QQ 和 OneBot 实机联调。
- 可读报告与 JSON 数据导出；导出不包含附件原文件和凭据，不支持恢复。
- 设置页支持检查旧版 JSON 或迁移 ZIP，确认后备份主数据库并迁入通知、草稿、任务、材料、多来源、旧历史及已打包原件。相同记录跳过，内容冲突阻止导入。旧版原件可通过 `scripts/pack_legacy.py` 从明确选择的数据目录打包。
- 学习通连接页支持对作业考试中心的缺失原件手动补下载，复用当前账号及原任务权限核对。已入箱的通知直接关联原件，任务仍走原审核流程。主项目单件上限 8 MB。
- 课程通知已记录的官方固定附件和内嵌图片也可手动补下载。下载限制为单件 8 MB，仅接受支持的官方地址和完整响应，下载后补到原通知。
- 已入箱通知可在「原始通知」区直接补下载支持的缺失原件。补收后原件显示在同一条通知下，可查看或手动重新识别。
- 如果本地原件文件丢失、采集记录仍保有原件副本，可在同一区域点「恢复原件」，沿用原附件关联与解析结果。恢复使用本地副本，无需再次请求学习通。
- 收件箱刷新后，附件从处理中变为失败时会显示可用的本机解析入口。重试失败原因直接显示在附件旁。隔离浏览器已使用模拟 OCR 故障验证此流程。
- 待审核通知中，成功提取的附件可就地发起「结合附件重新识别」。草稿已有手动修改时须确认后才会替换，取消会保留修改。
- 桌面采集确认通知详情稳定且正文为空时，保留通知标题和发布时间，并归入主项目收件箱的历史归档。正文尚未核实、发布时间未知或仍有附件及媒体的记录继续待核对。
- 只有附件的课程通知在原件到达后进入主收件箱待审核。无论原件来自后续同步还是手动补下载，均复用原采集记录。正文保持为空，提取附件文字后可重新识别，创建任务仍须用户确认。
- 同一课程通知的原件清单未变，且后续采集确认没有待收媒体并补齐原件时，原记录会解除媒体待收状态。重复收到较早的采集结果会保留已确认的状态，原件内容确实变化时另存版本。
- 参考 8877 的作业中心采集，在主入口显示本次连接的课程栏目检查回执。可请求优先重查该课程栏目，并导出只含同步状态和统计的检查报告。栏目已检查表示列表回执，正文与附件缺口仍须核对。栏目清单在采集器重连后重新发现。
- 栏目下可查看本次连接发现的作业或考试，并逐条请求补收。补收沿用同一采集器和收件箱。同步状态自动更新，主入口保留“重新检查”用于主动发起采集。
- 同步开启时，已下载的图片和 PDF 可进入现有本机附件队列，在支持 Windows OCR 的环境自动提取。仅识别了部分页面的 PDF 保留文字及说明，供用户对照原件核对。
- 严格匹配平台模板的纯倒计时提醒进入历史归档。附带新要求或变更的通知继续留给审核。
- 纯结束提醒也可归档。存在附件或媒体缺口时保留在收件箱，避免跳过附件里的新要求。明确的交卷和阅卷状态可建议记为已提交，退回重做可建议重新待办。状态更新仍需用户确认。
- 识别时将正文一致的完整附件视为同一份证据，并保留各附件原件。Windows OCR 可在时间预算内处理最多 30 页的 PDF。合成 12 页 PDF 验证读到了最后一页，英文识别可能出现额外空格。
- 具备明确平台身份、发布时间和原文的已提交或已结束作业及考试直接进入历史归档。原件仍可查看；后续状态变化以新同步记录核对。包含延期或取消线索的记录继续待人工核对。

- 签到到达平台截止时间，或收到同一账号与同一场次的明确结束记录后，从提醒列表移除，保留原任务和本地进度。

- 签到任务详情单独显示提醒状态。刷新本地记录后可看到该场签到是否已结束及提醒是否停止。
- 有完整课程、班级和作业或考试编号时，作业中心独立倒计时和采集编号变化可复用同一内容记录。实质内容变更仍产生新版本，旧重复记录保留。
- 微信和 QQ 连接页可打开文本粘贴表单。实际发送时间未知时可显式勾选，截止时间留给审核填写，规则识别仍会整理其他字段。群名和发件人可补在来源名称中。

## 旧版数据迁移操作

1. 在旧版导出 `courseinbox-backup.json`，保留旧数据目录。
2. 需要迁移已保存的附件原件时，在主项目根目录执行以下命令，将路径替换为自己选择的文件和目录。

   ```powershell
   .\backend\.venv\Scripts\python.exe scripts/pack_legacy.py --export 'D:\exports\courseinbox-backup.json' --data-dir 'D:\old-campus-inbox\data' --output 'D:\exports\migration.zip'
   ```

3. 在主项目的“设置 → 旧版数据迁移检查”选择 JSON 或 ZIP。检查新增、重复、冲突及缺失原件后勾选确认。同一批旧数据应使用相同的数据集名称。
4. 确认后，可在主项目任务详情查看关联原文、材料与旧版历史。迁移前的主数据库备份位于数据库旁的 `backups/`。旧版变更和取消草稿仍需人工核对，旧操作不会自动重放。

JSON 上限 10 MB，ZIP 上限 100 MB，迁移 ZIP 中单件原件上限 32 MB。打包只读取所选 JSON 引用且仍保存在旧数据目录中的原件。已有同编号记录发生变化时，请先核对冲突。缺失原件可随后用同一份 JSON 生成 ZIP，再以原数据集名称补入。

## 实际环境验收

1. 启动根目录主项目。在设置中预览自己选定的旧版备份，核对数量、冲突和缺失原件后导入。抽查任务状态、多个通知来源、材料和历史。
2. 在「设置 → 数据源连接 → 学习通」选择后台采集或网页组件。本人登录后，核对一条课程通知、一项作业或考试和一个带附件的通知。分别检查原文、发布时间、截止时间、收件箱草稿及附件。用补收入口复查同步报告列出的缺口。
3. 核对签到活动的起始时间和截止时间。同名但起始时间不同的签到应分别出现。已结束的签到应退出首页待办和提醒。
4. 核对通知创建任务、延期、取消及撤销。打开任务详情检查来源和历史，再到课务助手查询任务和材料。
5. 如需使用 QQ、微信推送、手机或托盘，在各自设置中单独配置并测试接收、故障恢复和关闭。保存问题时记录功能入口、时间和错误提示，隐去账号、凭据和消息原文。

## 主项目备份与恢复

停止主项目服务后，可在仓库根目录运行以下命令。备份包含 SQLite 数据和仍保存在本机的附件原件，可能包含个人通知和本机配对信息，请私下保管。

```powershell
.\backend\.venv\Scripts\python.exe scripts/backup_main.py create --database backend/data/campus-inbox.db --output campusinbox-backup.zip
.\backend\.venv\Scripts\python.exe scripts/backup_main.py restore --archive campusinbox-backup.zip --directory restored-data
```

恢复目录须是新目录。核对后，可将 `CAMPUSINBOX_DB_PATH` 指向其中的 `campus-inbox.db` 再启动主项目。学习通登录文件、外部服务配置和运行环境需另外配置。备份工具会报告找不到原件的数量。

## Windows 托盘提醒

启动主项目后，在仓库根目录运行 `.\scripts\start-tray.ps1`。托盘菜单可打开 CampusInbox、打开提醒页、暂停或恢复桌面提醒，以及退出托盘。主项目后端保持运行时，关闭网页仍可检查截止提醒。

托盘读取本机 8000 端口的提醒接口，点击通知会通过 5173 端口打开截止提醒页。通知回执保存在当前 Windows 用户的本地应用数据目录。浏览器通知和托盘通知独立开启，两者同时运行可能各显示一次。系统通知是否显示取决于 Windows 的通知设置。

Windows 验证通过了 .NET Framework 编译，以及使用隔离 HTTP 数据的托盘轮询、首次跳过已有提醒、排除已读提醒和新提醒去重。实际桌面通知显示与点击仍待实机验收。

主项目后端全量回归通过，共 551 项，前端 34 项及生产构建通过。用合成数据验证了空正文归档和只有附件的通知补收、去重与审核，以及多附件识别的冲突和部分 OCR 回归。Windows 本机 OCR 读出了合成图片中的测试文字，隔离浏览器验证了逐条补收、网页组件配对与撤销、课务助手查询和模型引用跳转。课务助手用隔离数据库和真实本机 Ollama 模型 `qwen3:4b-instruct` 验证了文件格式问答及正确的任务引用，单次请求耗时 74.1 秒。备份恢复用临时数据库和附件完成往返验证，并检查了目标目录覆盖和 ZIP 路径穿越的拒绝行为。
