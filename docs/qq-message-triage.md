# QQ 消息分流

QQ 接入先按配置的群和发送人筛选，再进入以下流程：

1. 任务线索白名单保护：考试、作业、通知、提交、截止、报告、实验、补交、取消、改期。命中只表示继续分析，不直接认定为任务。
2. 短回复黑名单：收到、好的、谢谢、哈哈、哈哈哈、嗯嗯、OK。最多 40 字，按空白、逗号、句号、感叹号等分段；只有每段都完整命中才跳过模型。匹配前统一全半角和英文大小写。
3. 其余消息交给已启用的本地 Ollama 模型，一次调用完成通知/聊天/不确定分类及任务字段提取。没有白名单关键词的消息也继续分析。

例如“好的，谢谢！”直接分流；“好的，明天交”继续分析；“这次考试好难”由模型判断是否为聊天。问号不作为短回复分隔符，避免把疑问当作确认回复。

分流消息保留在收件箱的“忽略消息”中，可恢复并重新识别。主动重新识别会跳过短回复规则。模型未启用、调用失败或结果无效时，消息进入“无法确认消息”。

收件箱导航只有“全部消息、重要消息、无法确认消息、忽略消息”。已识别的通知和已确认处理的消息归入重要消息；人工忽略优先归入忽略消息；恢复后的聊天、识别中的消息和未分类消息进入无法确认消息。待处理与已处理只作为消息状态展示。历史归档保留在全部消息中，可用“仅看历史归档”筛选。忽略、重要和无法确认三类互不重叠，不修改原有消息处理状态或历史数据。

当前复用已有的本地 Ollama 设置，没有独立的小模型分类服务；QQ 自动接收与重新识别均使用本地模型，不随手动导入的 API 模式切换。节省调用来自短回复规则，关键词保护本身不减少结构化提取所需的调用。手工粘贴和文件导入不受这些 QQ 规则影响。
