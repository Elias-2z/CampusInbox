## 当前交付

- 设置 → 数据源连接 → QQ：保存账号、群白名单、每群指定成员（空列表代表全群）、启用／暂停和配置修订。
- 统一适配器接口、真实发送时间校验、过滤自己发送／其他账号／未选择群和成员的消息。
- QQ 原始文本与账号、群、发件人、外部消息编号、发送时间保存在独立事件表。仅文本消息进入本阶段接口；图片等消息由未来适配器保留缺口，不能伪造成文字。
- 符合范围的事件先持久化，再调用已有规则优先／可选 Ollama 流程，生成同一收件箱中的建议；不直接创建、更新或取消正式任务。
- 同一标准事件重复上报幂等，正文或实际发送时间变化保留独立版本。QQ 外部身份去重与手动导入去重分别处理，同一天不同 QQ 消息编号不会被折叠。
- 批次先保存后推进游标；识别失败可显式重试；识别前落库、进程中断后可继续。创建通知后、事件回执保存前中断，重试复用原通知，不重复创建。
- 后端运行时约每 3 秒调用适配器检查新消息；关闭网页不停止后端。设置和游标持久化，重启后保留启用意图；会话是否仍有效由适配器报告。

**现已提供本机 OneBot HTTP 适配器（默认关闭），macOS 凭据使用钥匙串，Windows 使用系统凭据管理器。未安装或登录真实 QQ 消息桥时，界面仍报告未连接。Mac 的真实扫码与文本接收曾完成验证；Windows 的真实 QQ 联调、长期稳定性及完整补拉仍待验收。Mac 配置见 [接入文档](qq-mac.md)。**

## 给 Mac / Windows 实现者的接口

实现 `backend/src/campus_inbox/connectors/qq.py` 中的 `QQAdapter` 协议，通过 `create_app(qq_adapter=adapter)` 注入。适配器不直接写数据库、不调用任务创建接口。

| 方法 | 返回／行为 |
| --- | --- |
| `status()` | `AdapterState`：connected、account_id、name；不得包含 Cookie、Token 或原文 |
| `groups()` | `list[Group]`，群 ID、显示名称 |
| `members(group_id)` | `list[Member]`，成员 QQ 号、显示名称；按 ID 筛选，不依赖易变昵称 |
| `poll(cursor)` | `Batch(events, cursor)`，每批最多 100 条；无消息时返回空列表。失败抛异常，不能伪装成一次成功检查 |
| `disconnect()` | 释放连接和资源；不得删除 CampusInbox 事件、通知或任务 |

所有操作须使用有限网络超时，不得无限等待或在 `status()` 中扫码。登录与持久会话管理由平台适配器单独设计，下一阶段再提供图形登录流程。本阶段不存储登录凭据。实现者需保证游标可恢复、重复批次稳定；禁止用接收时间替换未知的实际发送时间。`Incoming` 拒绝无时区时间、缺失消息身份和空正文。

未来推送型桥接器可调用 `QQCore.receive(Incoming)`；`queued` / `duplicate` 表示已持久化或已有记录，`filtered` 表示未进入接收范围。队列满或写入异常必须让消息桥保留并重投。本机 OneBot 适配器提供带 HMAC 签名验证的 HTTP 上报端点，不能把核心管理 API 当作消息桥上报地址。

暂停后不再检查新批次；断开连接接口先持久暂停，再释放适配器。修改范围不会回抓先前被过滤的消息。已入队消息在识别前再次检查范围，不符合的保留为 blocked，重新允许后可继续。failed 不无限自动重试，需点击重试。正常每轮最多处理 10 条队列消息。

使用单个后端进程（单 Uvicorn worker），核心用进程内锁协调配置与处理。若启用多个后端进程，需先补数据库队列抢占／租约，不在本阶段支持范围内。模型识别期间不占用数据库写事务；配置操作可能等待当前识别结束。

## 本机管理 API

| 路径 | 用途 |
| --- | --- |
| `GET /api/connectors/qq` | 配置、适配器状态、队列计数、最近接收／检查时间与脱敏错误 |
| `PUT /api/connectors/qq/settings` | 保存 `Config`，必须携带当前 revision；旧修订返回 409 |
| `GET /api/connectors/qq/groups` | 读取群列表 |
| `GET /api/connectors/qq/groups/{id}/members` | 读取成员列表 |
| `POST /api/connectors/qq/sync` | 检查已保存范围并处理持久队列 |
| `POST /api/connectors/qq/retry` | 将失败事件重新排队并检查 |
| `POST /api/connectors/qq/disconnect` | 暂停检测并断开适配器，保留选择与历史 |
| `GET /api/connectors/qq/events?state=failed` | 最近 50 条事件，包含原文、QQ 身份及 suggestion_id；只供本机使用 |

沿用应用本机单用户边界，服务只绑定回环地址，不开放公网。配置 API 不用于接收外部消息桥请求。不要将真实群消息、账号会话或生产数据库提交 Git。

## 群名与课程映射

每个群可设置对应课程，默认跟随群名；可改为规范课程名称，显式留空则不补充。原文明示课程时优先保留原文识别结果。仅在课程缺失时采用群设置，证据标为“群课程设置”，不拼接或修改通知原文。课程映射在接收时保存快照，改名后不会因重复投递或重新识别改写旧通知的来源上下文；升级前的待审核消息首次重新识别时可从当前群选择补一次快照。

新增 4 项回归验证默认群名、别名、留空禁用、原文优先、重新识别与修改映射后的去重。完整检查更新为 273 项后端测试通过；前端日期、lint、格式、类型与构建通过。

## 课程名清理、结构化上下文与来源显示

群课程自动建议先清理明确的年份、学期、班级及群后缀，保留 A、Ⅲ、课程自身数字等；无法从“2026级三班通知群”等名称明确课程时返回空值，不补造。设置中的“智能识别课程名”可按需调用已配置的本机模型；候选必须能在原群名找到依据，且仍需用户保存确认。自定义别名和留空禁用保持优先。

原文、群名、课程、发件人、实际发送时间分别保存。本机模型通过 `generate_contextual` 接收独立的 source_context，通知原文不拼接元数据。群名中的年份不用于截止日期计算，发件人不充当课程；模型输出仍校验通知原文依据，课程上下文由业务层补充。模型上下文不发送群号或 QQ 身份编号。

消息 API 提供 source_context，展示用 source 优先使用课程／群名和群名片／昵称，获取不到发件人名称时回退 QQ 号。原群名、群号和发件人编号可在收件箱详情查看；数据库原 source、原文与去重身份不修改，发件人改名不重复入队。新事件保存群名和发件人名称快照；旧消息没有的发件人名称不编造。
